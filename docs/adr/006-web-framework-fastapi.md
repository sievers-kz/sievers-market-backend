# ADR 006: Выбор FastAPI как основного веб-фреймворка

## Status
`ACCEPTED`

## Context
При выборе веб-фреймворка ключевыми требованиями были:
- **Архитектурная свобода:** проект строится на DDD + Clean Architecture — фреймворк не должен навязывать структуру кода, доменных моделей или базы данных;
- **Нативный asyncio:** весь инфраструктурный стек асинхронный (SQLAlchemy async, ARQ, aioredis) — фреймворк должен быть асинхронным по своей природе, а не в виде надстройки;
- **Интеграция:** совместимость с выбранными библиотеками без дополнительных архитектурных обёрток.

## Alternatives

### 1. Django / DRF `Rejected`
**Причины отказа:**
- **Навязывает структуру:** Django диктует жесткую организацию кода, структуру моделей и наследование (например, `AbstractUser`), что напрямую конфликтует с границами контекстов (Bounded Contexts) в DDD;
- **Конфликт паттернов ORM:** Django ORM жестко завязана на паттерн *Active Record*. Для Clean Architecture требуется паттерн *Data Mapper (Repository)*, реализуемый в SQLAlchemy, чтобы изолировать доменные сущности от деталей инфраструктуры хранения;
- **Инфраструктурный оверхед:** отказ от Django ORM требует значительных усилий; при этом Django принудительно создаёт системные таблицы (`auth_permissions`, `django_migrations` и др.), которые избыточны для данного проекта;
- **Async как надстройка:** исторически экосистема Django синхронная. Поддержка async внедряется постепенно и остаётся неполноценной на уровне многих внутренних компонентов и сторонних плагинов;
- **Высокий уровень неявных абстракций:** скрытые под капотом механизмы Django усложняют явный контроль над жизненным циклом запроса и транзакций.

## Decision
Использовать **FastAPI** как основной веб-фреймворк.

**Обоснование:**
1. **Архитектурная свобода:** FastAPI не навязывает структуру проекта — организация кода, моделей и слоёв полностью определяется архитектурными решениями проекта;
2. **Нативный asyncio:** FastAPI построен на Starlette и asyncio — естественно интегрируется с SQLAlchemy async, ARQ, aioredis без блокирования event loop;
3. **Pydantic из коробки:** валидация входящих данных, сериализация ответов на уровне DTO и автогенерация OpenAPI схемы происходят декларативно через типы данных;
4. **Производительность:** минимальный оверхед самого фреймворка при обработке HTTP-запросов по сравнению с тяжеловесными альтернативами.

## Consequences
**Positive:**
- **Полный контроль:** структура проекта полностью изолирована от конвенций веб-фреймворка;
- **Единая модель конкурентности:** весь стек работает на asyncio без рисков взаимной блокировки потоков при смешивании синхронного и асинхронного кода;
- **Автодокументация:** OpenAPI / Swagger генерируются на лету, выступая в роли актуального контракта для внешних интеграций.

**Negative:**
- **Отсутствие встроенных компонентов («батареек»):** каждый инфраструктурный компонент (миграции, фоновые задачи, отправка почты) выбирается, настраивается и интегрируется вручную;
- **Отсутствие административной панели:** для закрытия потребности в операционном интерфейсе управления данными в проект добавлена дополнительная зависимость `SQLAdmin`.
