# ADR 005: Выбор ARQ для фоновых задач

## Status
`ACCEPTED`

## Context
Система требует механизма выполнения фоновых задач асинхронного стека:
- **Текущее:** отправка email (подтверждение регистрации, уведомления);
- **Запланировано:** ресайз превью изображения при создании листинга.

Требования:
- **Нативный asyncio:** совместимость с async стеком без обёрток;
- **Персистентность:** задача не должна теряться при перезапуске сервиса;
- **Минимум инфраструктуры:** Redis уже в стеке.

## Alternatives

### 1. Celery `Rejected`
**Причины отказа:**
- Синхронный по природе — в async стеке требует `gevent` или `eventlet`
  как обходные пути, что создаёт friction с asyncio event loop;
- Инфраструктурно тяжелее — требует отдельного воркер-процесса и
  beat-процесса для cron задач;
- Избыточен для текущего объёма задач.

### 2. FastAPI Background Tasks `Rejected`
**Причины отказа:**
- Нет персистентности — задача выполняется в рамках HTTP запроса,
  теряется при перезапуске сервиса;
- Нет retry механизма — при падении задачи (например, недоступность
  SMTP) повтор не происходит;
- Нет очереди — задачи не буферизируются, выполняются конкурентно
  в том же процессе.

## Decision
Использовать **ARQ** как механизм фоновых задач поверх существующего Redis.

**Обоснование:**
1. **Нативный asyncio:** ARQ построен на asyncio — не требует обёрток
   и естественно интегрируется в async стек;
2. **Минимум инфраструктуры:** работает поверх Redis который уже в стеке —
   не требует дополнительного брокера;
3. **Персистентность и retry:** задачи хранятся в Redis, при падении
   воркера не теряются, поддерживается retry;
4. **Cron из коробки:** поддержка периодических задач через `cron_jobs`
   без дополнительных зависимостей.

## Consequences
**Positive:**
- **Совместимость:** нативная интеграция с async стеком без компромиссов;
- **Простота:** один процесс воркера, Redis уже в стеке, минимум настройки;
- **Надёжность:** персистентность задач и retry механизм из коробки.

**Negative:**
- **Меньше экосистемы:** ARQ значительно моложе Celery — меньше
  документации, плагинов, готовых решений;
- **Меньше мониторинга:** нет встроенного UI для мониторинга задач
  (в отличие от Flower для Celery).
