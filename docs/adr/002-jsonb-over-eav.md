# ADR 002: Выбор JSONB и отказ от EAV для хранения динамических атрибутов

## Status
`ACCEPTED`

## Context
При проектировании системы возникла необходимость хранить динамический набор атрибутов
для подкатегорий рубрики "Техника" (Тракторы, Комбайны, Автотранспорт и др.).

Требования:
- **Гибкость схемы:** возможность добавления атрибутов без изменения SQL-схемы;
- **Архитектурная чистота:** чёткое разделение между схемой атрибутов (подкатегория)
  и значениями атрибутов (листинг);
- **Минимум инфраструктуры:** решение в рамках существующего стека.

## Alternatives

### 1. EAV `Rejected`
**Причины отказа:**
- Сложные многоуровневые JOIN при получении атрибутов листинга;
- Отсутствие типизации на уровне БД — все значения хранятся как VARCHAR;
- Размытие границы между схемой и значениями атрибутов — оба понятия
  размазываются по нескольким таблицам.

### 2. MongoDB `Rejected`
**Причины отказа:**
- Отсутствие реляционных связей и UUID-типизации усложняет интеграцию
  с существующей реляционной схемой;
- Лишняя инфраструктура — PostgreSQL с JSONB покрывает все требования.

## Decision
Использовать **JSONB** в PostgreSQL для хранения динамических атрибутов.

**Обоснование:**
1. **Гибкость схемы:** добавление нового атрибута к подкатегории не требует
   ALTER TABLE — схема обновляется на уровне данных подкатегории;
2. **Архитектурное разделение:** подкатегория владеет схемой атрибутов,
   листинг хранит только значения (`engine_power: 123`). EAV размазал бы
   эту границу по нескольким таблицам и усложнил доменную модель;
3. **PostgreSQL уже в стеке:** JSONB покрывает требования без введения
   дополнительной инфраструктуры.

## Consequences
**Positive:**
- **Гибкость:** новые атрибуты подкатегорий добавляются без миграций схемы БД;
- **Чистота доменной модели:** граница между схемой и значениями атрибутов
  чётко выражена на уровне архитектуры;
- **Простота запросов:** атрибуты листинга извлекаются одним запросом
  без JOIN.

**Negative:**
- **Смещение валидации:** типизация и структура атрибутов не гарантируется
  на уровне БД — валидация полностью на уровне приложения;
- **Неудобство администрирования:** стандартные инструменты (SQLAdmin)
  отображают raw JSON — для комфортной работы администратора требуется
  специализированный UI который динамически рендерит форму по схеме
  подкатегории.
